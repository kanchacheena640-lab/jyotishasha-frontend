# Jyotishasha Subject Hub Standard

Reference standard for every Jyotishasha subject hub (a page that introduces one subject and routes visitors to its guides, free tools and reports). The Marriage Hub (`/marriage-astrology`, `/hi/marriage-astrology`) is the reference implementation:

- Route: `app/[locale]/marriage-astrology/page.tsx`
- Renderer: `components/authority-engine/IntentHubRenderer.tsx`
- Content/config: `lib/domains/marriage-astrology/_hub.ts`
- Domain metadata: `lib/domains/marriage-astrology/_meta.ts`
- SEO helpers: `lib/authority-engine/seo.ts`
- Regression baseline: `lib/fixtures/marriage-cluster-baseline.json` (MC-02 snapshot)

This document describes conventions. It does not authorise refactoring other hubs; each hub adopts it in its own approved change.

---

## 1. Information architecture

A hub answers "what can I find out about this subject here?" and sends each visitor to the right next page. Sections, in this order:

| # | Section | Purpose | Element |
|---|---|---|---|
| 0 | Breadcrumb | Where the page sits | `<nav aria-label>` + `<ol>` |
| 1 | Hero | H1 + one-line lead + the visitor's real questions | `<header>`, H1, question cards |
| 2 | Free tools | Calculators for the subject (+ related calendar, e.g. Muhurat) | H2 + tool cards |
| 3 | Personalised reports | Featured report, other reports, focused question cards, "see all" links | H2 + cards |
| 4 | Explore the subject | Every guide of the subject, grouped by sub-topic, each linked exactly once | H2 + grouped link lists |
| 5 | How the subject is read | Short original explainer of the method, linking to the in-depth guides | H2 + H3 items |

Rules:
- A hub links only to **existing** routes. It never creates category routes or URLs of its own.
- Every guide of the subject appears **exactly once** in section 4 (the guard test enforces no unknown or duplicate slugs).
- Question cards (section 1) each map to the single most relevant existing guide. Record the reasoning in the config when the choice is not obvious.
- Names, prices and focused-report questions are read from the catalogs (`app/data/reportsData.ts`, `app/data/focusedReportsConfig.ts`) at render time, never retyped in hub config.
- The focused-report catalog is reached only through `focusedReportsConfig.ts` (the approved entry point; `lib/intentCatalog.test.ts` enforces this).

## 2. Breadcrumb and structured data

### Breadcrumb
- Visible breadcrumb: `Home › <Subject>` (Hindi: `होम › <विषय>`), labels from `UI_LABELS.home` and the domain `label`.
- The last item is the current page: plain text with `aria-current="page"`, not a link.
- Home links to the **final** URL: `/` (EN) and `/hi` (HI). `/hi/` 308-redirects to `/hi` and must not be used.
- JSON-LD: one `BreadcrumbList` built with `buildAuthorityBreadcrumbSchema(domain, null, locale, authorityHomeUrl(locale))`. The visible and structured breadcrumbs must have the same items, names and URLs.

### Schema policy
- Add a schema type only when the page is eligible under Google's guidelines **and** the marked-up content is visible on the page. Never add schema to raise a count.

| Type | Hub | Reason |
|---|---|---|
| `BreadcrumbList` | Yes | Matches the visible breadcrumb |
| `FAQPage` | No, unless the hub shows real FAQs | Must mirror visible Q&A exactly |
| `Article` | No | A hub is navigation, not an article (Article belongs on the guides) |
| `WebPage` / `CollectionPage` / `ItemList` | No | No rich result for this page type; the links are already crawlable HTML |
| `Organization` | No | Lives on the home page only (`app/[locale]/page.tsx`) |

- One block per type per page; no duplicates from shared layouts (root layouts emit none).
- JSON-LD is rendered in the route file (server component), as the guides do.

## 3. Metadata and headings

- **Title:** unique, subject-first, ≤ 60 characters where possible (EN reference: "Marriage Astrology: Vedic Guide, Free Tools & Reports", 53). Hindi titles follow the same pattern; keep them as short as the language allows.
- **Meta description:** ≤ 160 characters, describes the subject, the free tools and the reports honestly.
- **Open Graph title/description:** same as title/description.
- **Canonical:** self-referencing (`/subject`, `/hi/subject`). Never pointed elsewhere.
- **hreflang:** `en`, `hi`, `x-default` (= EN), absolute URLs. Generated by `generateAuthorityHubMetadata`; hubs override only title/description.
- **Robots:** no directive (indexable). Hubs are in the sitemap with their Hindi counterpart.
- **Headings:** exactly one H1 (the subject name, short). Each section is an H2; cards/groups inside a section are H3. No skipped levels, no title-like H2 that repeats the H1.

## 4. Internal linking

- Hub → every guide (once in section 4; question cards and the explainer may link again where genuinely helpful).
- Hub → every free tool of the subject and its calendar page (e.g. Muhurat), localized (`/hi/...` for Hindi).
- Hub → featured and related paid reports, plus "see all reports" and "see all focused reports" (existing catalog routes only).
- Hub → supporting foundation pages (e.g. planet-in-7th-house) from the explainer, where they add depth.
- Guides → hub: through their breadcrumb (`Home › Subject › Guide`) and BreadcrumbList.
- Links are plain crawlable `<a href>` (Next `<Link>`), never `onClick` navigation.
- A Hindi link that lands on an English-only page carries a short visible notice saying so.
- Every link must return HTTP 200 without redirect (checked in validation).

## 5. Content quality

- Every word is server-rendered (no client-only content, no content behind interaction).
- The hub explains its subject in a short, original section (section 5): what is read, why, and where to go deeper. Factual and careful: describe tendencies, never promise outcomes, dates or certainty.
- Report descriptions only name sections the backend generator actually writes. Never claim remedies, timing or analyses the PDF does not contain.
- No filler, keyword stuffing or duplicated guide text. Aim for useful density over length.
- No invented keyword volumes, rankings or statistics anywhere in copy or reports.

## 6. Mobile and accessibility

- Mobile-first: verified at 390 px, 768 px and 1366 px; no horizontal overflow.
- Tap targets ≥ 44 × 44 px for every link (cards, breadcrumb, link lists).
- Visible focus style on every link (`focus-visible:ring-2`).
- Text contrast ≥ 4.5:1 (reference palette: navy `#1B2A4A`, body `#45516A`, muted `#5B667D`, terracotta `#A8461F` on ivory `#FBF8F2` / white; lowest measured pair 5.5:1).
- Decorative icons/emoji are `aria-hidden`.
- No text truncation of questions or prices; questions wrap naturally.
- Fixed site-wide layers (header, WhatsApp button, app-download bar, cookie banner, Auto Ads) are site-wide and changed only with separate approval; a hub must not add its own fixed overlays.
- Core Web Vitals: hubs are static (SSG + ISR), no images above the fold, no client JavaScript of their own.

## 7. Hindi localization

- Every visible string has a natural Hindi version (`*_hi` fields), not a literal word-for-word translation.
- Hindi routes live under `/hi`; all internal links on a Hindi page use `/hi` routes where they exist.
- The hub's `<main>` carries `lang="hi"` on Hindi pages. Known site-wide gap: the shared root `<html>` is always `lang="en"` (`app/layout.tsx`); fixing it is a separate, site-wide change.
- Hindi metadata (title, description, Open Graph) and BreadcrumbList names are localized.

## 8. Validation checklist

Run locally against a production build (`next build` + `next start`); the live site is behind a Vercel bot challenge, so record live checks separately as verified by a person in a browser.

- [ ] `tsc --noEmit -p .` — 0 errors
- [ ] ESLint on changed files — clean
- [ ] `next build` — exit 0, hub routes prerendered
- [ ] Guard, SSR, snapshot, Article-schema and FAQ-schema tests for the subject — pass
- [ ] Snapshot baseline: only the hub entries change; review the diff; restore the Search Console template if the update mode rewrote it
- [ ] Rendered HTML (EN + HI): status 200, one H1, H2/H3 order, server-rendered content
- [ ] Title/description lengths; canonical self; hreflang `en`/`hi`/`x-default`; no robots directive
- [ ] JSON-LD parses; only the approved types; no duplicates; BreadcrumbList matches the visible breadcrumb; no breadcrumb URL redirects
- [ ] Every internal link returns 200 without redirect
- [ ] 390 / 768 / 1366 px: no overflow, no clipped text, tap targets ≥ 44 px, focus styles, contrast
- [ ] Hindi page: `lang="hi"` on main, all links localized, English-only destinations flagged
- [ ] After deployment: open both live URLs in a browser and confirm the above by eye
